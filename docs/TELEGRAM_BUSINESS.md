# Telegram: обычный бот и Telegram Business

## Два режима

| | Обычный бот | Telegram Business |
|---|---|---|
| Куда пишет пациент | в бота клиники | в **личный аккаунт клиники** |
| Что видит пациент | бот | привычный чат с клиникой |
| Кому нужен | клиникам без аккаунта в Telegram | тем, у кого уже есть живой чат и история |
| Что меняется в коде | ничего | обновления приходят как `business_message`, ответ несёт `business_connection_id` |

Логика диалога, слоты, промпт, передачи человеку — одинаковые. Разница только в
транспорте, и она изолирована в `arix/channels/telegram.py`.

## Подключение обычного бота

1. Получить токен у [@BotFather](https://t.me/BotFather).
2. ```bash
   cd backend
   python -m arix.cli connect-telegram --slug <slug> --token <BOT_TOKEN>
   ```
   Поставится вебхук `POST {PUBLIC_BASE_URL}/webhooks/tg/<slug>` с секретом
   `TELEGRAM_WEBHOOK_SECRET`; разрешённые апдейты включают `business_connection`
   и `business_message`.

## Подключение Telegram Business

Нужен Telegram Premium на аккаунте клиники (требование Telegram для
бизнес-функций).

1. Подключить бота как выше, с `--business`:
   ```bash
   python -m arix.cli connect-telegram --slug <slug> --token <BOT_TOKEN> --business
   ```
2. На телефоне клиники: **Настройки → Telegram для бизнеса → Чат-боты** →
   указать username бота → включить **«Разрешить отвечать на сообщения»**.
3. Telegram пришлёт апдейт `business_connection`. Бэкенд сохранит
   `business_connection_id` и `owner_user_id` в настройках канала, статус
   канала станет `connected` — это видно в панели.

Проверка: напишите в аккаунт клиники с другого телефона. Ответ придёт в том же
чате, от имени клиники.

## Как мы не мешаем живому администратору

В Telegram Business сообщения, отправленные **самим аккаунтом клиники**, тоже
приходят боту. Мы помечаем их `from_business` и делаем из этого фичу:

- такое сообщение не считается вопросом пациента;
- диалог переводится в `with_human`, и бот в нём замолкает;
- лестница дожима по этому диалогу отменяется.

То есть администратор просто начинает писать сам — и бот уходит в сторону.
Вернуть диалог боту можно кнопкой «Вернуть боту» в карточке передачи или в
панели.

## Общий бот ARIX для демо и мелких тенантов

Один бот обслуживает много клиник: вебхук `POST /webhooks/tg/shared`, а
маршрутизация по диплинку `?start=t_<slug>`. Связка «пользователь Telegram →
тенант» хранится в `channel_routes` и живёт до следующего диплинка. Так демо
для десяти клиник работают с одного токена.

## Боты персонала

Администратор, владелец и врач пишут тому же боту в личный чат. Роль берётся
из таблицы `staff` по `tg_user_id`, а не из того, какой бот ответил.

| Команда | Роль | Что делает |
|---|---|---|
| `/today` | все | приёмы на сегодня; врачу — его расписание с кнопками «пришёл / не пришёл» |
| `/tomorrow` | врач | расписание на завтра |
| `/week` | админ, владелец | загрузка по дням |
| `/report` | владелец | утренний отчёт за вчера |
| `/handoffs` | админ | открытые передачи |
| `/lost` | админ, владелец | кто спросил и не записался |
| `/reviews` | владелец | отзывы за 30 дней |
| `/prices код от [до]` | владелец | быстро поменять цену |
| `/off Имя врача ГГГГ-ММ-ДД` | админ, владелец | врач не работает в этот день |
| `/pause_bot`, `/resume_bot` | админ, владелец | остановить и включить бота |

Карточка передачи приходит с кнопками «Беру», «Вернуть боту», «Диалог».
Если за `handoff.pickup_minutes` (10 по умолчанию) никто не взял — напоминание
администратору, через `escalate_minutes` (30) — владельцу. Ночью передачи
копятся и приходят пакетом в 09:00.

## Диагностика

```bash
curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"
docker compose logs -f backend | grep -E "telegram|business_connection"
```

| Симптом | Причина |
|---|---|
| 401 на вебхуке | не совпал `TELEGRAM_WEBHOOK_SECRET` |
| бот молчит в Business-чате | не включено «Разрешить отвечать» в настройках аккаунта |
| бот отвечает в личке, но не в Business | в `allowed_updates` нет `business_message` — переподключите канал |
| сообщения от клиники считаются вопросами | обновите бэкенд: `from_business` появился именно для этого |

# Персональные данные и безопасность

## Принцип: собираем минимум

Для записи нужны имя, телефон, услуга и время. Мы **не спрашиваем** ИИН,
диагнозы, анамнез, документы. Жалоба пациента используется только для подбора
услуги (`route_by_complaint`) и не хранится как медицинская запись.

## Согласие

- При первой записи бот показывает короткий текст и просит подтверждение.
  Отметка времени — `contacts.consent_pd_at`. Без неё `confirm_booking`
  возвращает `missing_fields` и запись не подтверждается.
- Маркетинговые сообщения («давно не были», реактивация) уходят **только** при
  `contacts.consent_marketing_at`. Это проверяется в `domain/messaging.py`, а не
  в тексте промпта.
- «Стоп» в любом виде ставит `opted_out_at` и отменяет лестницу дожима
  немедленно, до обращения к модели.

## Маскирование перед LLM

`core/pii.py` заменяет токенами телефоны, ИИН/ПИНФЛ (12 и 14 цифр), e-mail,
номера карт и имя контакта из базы:

```
«Меня зовут Айгерим, телефон +7 777 123 45 67, ИИН 870512300123»
→ «Меня зовут [NAME_1], телефон [PHONE_1], ИИН [NATID_1]»
```

Хранилище токенов живёт один ход диалога: ответ модели разворачивается обратно,
пациент видит своё имя, провайдер — только токены. Цены и время не маскируются
(«15 000 тенге», «10:00») — иначе агент не смог бы работать.

Выключается `PII_MASKING_ENABLED=false`. Для медицинских тенантов выключать
нельзя.

## Казахстан

Медицинские данные — ПД ограниченного доступа, хранение и обработка должны быть
на серверах в РК.

- Для KZ-тенантов поднимается отдельный инстанс с БД и медиа в Казахстане;
  `DATA_REGION=kz` проставляется в `tenants.data_region` для аудита.
- В зарубежный LLM уходит только обезличенный текст (маски) и только при
  наличии согласия.
- Для полной локализации обработки голоса `STT_PROVIDER=local` указывает на
  свой faster-whisper рядом с БД.
- Шифрование: TLS в транспорте, учётные данные каналов — Fernet в
  `channels.credentials_enc`, тома БД шифруются на уровне диска.
- Журнал доступа — `audit_log` (кто, что, когда, с какого IP).

## Узбекистан

С поправок 2026 года обязательная локализация осталась для биометрических и
генетических данных. Мы их не собираем, поэтому остальное можно обрабатывать
за рубежом при соблюдении условий.

## Права пациента

| Запрос | Что происходит |
|---|---|
| «удалите мои данные» | `precheck` ловит до модели → передача с приоритетом `high` → пациенту ответ про 15 рабочих дней |
| «не пишите мне» | `opted_out_at`, рассылки прекращаются сразу |
| «позовите человека» | передача без уговоров |

Анонимизация ставит `contacts.anonymized_at`; после этого `send_message`
отказывается отправлять что-либо такому контакту.

## Изоляция тенантов

Две независимые преграды, см. [ARCHITECTURE.md](ARCHITECTURE.md):

1. RLS в Postgres на `current_setting('arix.tenant_id')` с
   `FORCE ROW LEVEL SECURITY`;
2. фильтр `tenant_id` во всех запросах приложения.

**Роль приложения не должна быть суперпользователем** — иначе Postgres
пропускает политики. `scripts/init-db.sql` создаёт `arix_app`, и
`docker-compose.yml` подключается именно им. Тест
`tests/test_tenancy.py::test_rls_blocks_cross_tenant_reads` проверяет это на
настоящей не-суперпользовательской роли: чужие строки не читаются, вставка
чужого `tenant_id` запрещена `WITH CHECK`.

## Секреты

| Переменная | Что это |
|---|---|
| `SECRET_KEY` | подпись JWT панели; из него же выводится ключ шифрования, если не задан свой |
| `CREDENTIALS_ENCRYPTION_KEY` | Fernet-ключ для токенов каналов; в проде задавать явно |
| `ADMIN_API_TOKEN` | суперадмин ARIX, header `X-Arix-Admin-Token` |
| `TELEGRAM_WEBHOOK_SECRET` | Telegram присылает в `X-Telegram-Bot-Api-Secret-Token` |
| `WA_WEBHOOK_SECRET` | HMAC подписи от сайдкара WhatsApp |
| `WA_BAILEYS_TOKEN` | bearer для вызовов бэкенд → сайдкар |

Сгенерировать ключ шифрования:

```bash
python -c "import base64,os;print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

Ротация `CREDENTIALS_ENCRYPTION_KEY` требует перевыпуска учётных данных
каналов: токены, зашифрованные старым ключом, прочитать не получится, и
`decrypt_json` вернёт пустой словарь, а не упадёт.

## Доступы и защита API

- Панель — JWT, роль берётся из `staff`; срок `JWT_TTL_MINUTES`.
- Пароли — bcrypt (cost 12), длинные пароли предварительно хешируются SHA-256,
  потому что bcrypt молча обрезает всё после 72 байт.
- Сравнение пароля выполняется всегда, даже когда пользователя нет, чтобы по
  времени ответа нельзя было перечислять аккаунты.
- Mini App — подпись Telegram `initData` (HMAC по токену бота) с проверкой
  срока; контакт берётся из подписанных данных, а не из тела запроса, поэтому
  чужие записи увидеть нельзя.
- Вебхуки платежей — подпись провайдера (`verify_click_signature` для Click).
- 2FA в панели — в планах; до неё доступ к панели ограничивайте по IP.

## Что делать перед первым крупным клиентом

1. Задать свои `SECRET_KEY`, `ADMIN_API_TOKEN`, `CREDENTIALS_ENCRYPTION_KEY`.
2. Проверить, что приложение подключается не суперпользователем:
   `docker compose exec backend python -c "from arix.config import get_settings;print(get_settings().database_url)"`.
3. Включить ежедневные бэкапы БД с хранением 30 дней.
4. Поднять инстанс в РК для KZ-клиник.
5. Отдать тексты согласия и политики местному юристу.
